# Research kit: reviewed analysis and scientific visualization sources

Public optional source pack for BioResearchWorkbench. The initial workbench foundation is Biomni; the host supplies reasoning. This pack adds independently maintained method-specific adapters, QC, complete-result contracts, review ledgers and frozen-result visualization. Original scientific algorithms, repositories, model weights, databases, viewers and fonts retain their own authorship and terms.

The source is public; project data, generated receipts/configuration and credentials remain private. Legacy `.private` static source filenames have public aliases, while private generated-result filenames and rejection rules remain intact. The original 71-entry registry is byte-preserved; its historical status fields do not describe current server availability. Current overlays state `NOT_RUN_THIS_UPGRADE`, `NOT_PROBED_THIS_UPGRADE` and `NOT_ESTABLISHED`.

## Calling the source

Use an explicitly selected existing bridge through `BIORESEARCH_BRIDGE_ROOT` or an ignored `deployment.local.json`. A template is provided. No personal endpoint, model key, registration change or automatic engine/model installation is included.

```text
cd research_kit/workflow_integration
python workbench.py plan --request PROJECT.json --out FRESH_BUNDLE
```

This prepares a request only. Dispatch explicitly through the existing shared SSH/scheduler to a current compute node. Inspect fresh actual engine completion, full result proofs, method QC and scientific context before `accept` or `figure-plan`. Unknown submissions are never automatically retried.

`scientific-visualization` consumes supplied results; it does not silently refit analyses, embeddings, models, intervals or enrichments. SHAP's small inset rose remains the default. Old plotting forms are preserved. A separate figure repository retains all previous historical recipes and provides this public skill with examples.

## Validation and limits

Run `python research_kit/run_checks.py` from the repository checkout with the CI-only dependencies in `requirements-ci.txt`. It uses the existing core statistics consultation; no duplicate function or success stub is shipped. Contracts, source checks and display tests do not execute scientific engines. These dependencies are not added to the lightweight default core installation.

The carried local evidence covers 632 contract/compatibility tests and sixteen reviewed frozen public-result displays at single/double-column widths. Fresh public source checks are recorded separately. This is not a fresh complete 140-template/interactive/browser audit or real HPC/scientific acceptance. The actual MorphDiff five-channel generated output has not been reviewed because no native result exists.

CSI:FingerID imports real source-bound results only. A fresh proprietary online prediction is outside these routes. scDiffusion real-start-cell gradient interpolation is not implemented by the declared generation route. MorphDiff's pinned sampler requires an existing server CUDA environment. License, weight and dependency availability remain actual preconditions; MAGPIE's absent top-level license, Squidiff's conflicted license text and Stack's distinct model/output terms are not silently treated as permission.
