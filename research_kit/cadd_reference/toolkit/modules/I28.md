# I28 失败恢复与模块升级验收

版本 3.0.0

### 失败先分类再重试

任务失败至少区分输入身份错误、化学准备失败、方法不适用、软件执行失败、资源或文件系统失败、科学验收不通过和结果无法区分假设。前两类返回输入或模型准备，资源故障可在输入不变时恢复任务，方法不适用应更换方案。对科学验收失败进行无上限自动重试通常不能解决原因。

| 现象 | 先核对的证据 | 下一步 |
|---|---|---|
| 对接返回空输出 | 输入分子与网格、日志、退出码和搜索状态 | 区分合法零结果、输入错误和程序失败 |
| MD 出现非物理距离或约束报错 | 原始建模、参数、限制、最小化和首个异常帧 | 修复受影响模型并重新完成相应平衡 |
| 新旧轨迹无法拼接 | 原子顺序、拓扑、时间、盒、运行与续段身份 | 从一致的源数据重建；不按文件名强行拼接 |
| 端点能量或自由能不稳定 | 选择、单位、模型、重复和采样诊断 | 重新定义比较或增加有针对性的采样 |
| 新模型指标大幅提升 | 数据分割、标签泄漏、重复实体与调参过程 | 重做冻结验证并记录已泄露测试版本 |
| 增量脚本拒绝复用 | 指纹组成、输出哈希、证据文件和依赖状态 | 解释实际变化后重算或补回已验证的原件 |

每次重试使用 attempt_id，记录原任务、失败原因、修改项和是否改变科学模型。相同输入因节点中断而重启可以是同一任务的执行重试；改变质子化、力场或分析阈值应形成新参数或模型版本。无论是哪种情况，都不覆盖原失败日志。

### 模块升级的验收集合

升级专用软件、模型权重、参数库或接口后，先用代表性案例做接口和科学回归。接口验收关注字段、文件、单位、顺序、失败处理；科学验收关注当前项目实际需要保持的观测量、排序或统计性质。浮点结果不必逐位相同，但差异容许范围必须依研究问题说明，不能以“新版本”作为所有差异都合理的解释。

至少准备一例已知正常输入、一例明确无效输入、一例边界或特殊结构，以及一个保留的参照结果。升级只影响作图时，不重复真实 MD；升级改变能量模型时，旧轨迹不能被包装成新力场模拟。模型转换验收应包括原子/残基顺序、键合与非键合参数、约束、排除和单位，并按适用情形检查相同坐标下的能量或力。

### 版本发布与退出条件

release_manifest 指定项目版本、使用的任务状态、数据和代码哈希、图形、主要结论、限制和待补工作。将 accepted、superseded、failed 与未完成项分开，保留已发布结果的不可变快照。新结论若与旧版不同，应能定位到新增数据、改进方法、错误修正或新的解释，而不是让旧文件默默消失。

本版模板包提供模块登记、计划器、排名比较器、图形入口和交接模板。是否进入下一模块由相应科学关卡决定：无法确定化学状态时先解决模型；方法在当前靶点无法恢复参照时先修正方法；采样不足时保留不确定性；生物学统计缺少独立重复时降低结论范围。达到预先定义的用途与证据标准后，冻结当前版本并结束该轮计算。
