# I24 新数据接入与结果复用计划

版本 3.0.0

### 触发条件与任务指纹

每当新增数据或修改分析规则时，先运行本模块，产出受影响任务及原因，随后才安排计算。常见工作流系统会同时考虑代码、输入、参数和环境，恢复也依赖保留下来的结果文件。Nextflow 默认文件缓存与严格内容哈希的语义不同，须按实际配置理解；本包规划器逐字节计算 SHA256。[IE01,IE02]

本包任务指纹包含项目和任务身份、对象与任务类型、直接输入内容、方法参数、程序身份、适配代码内容、上游已验收任务的指纹及输出路径。被实际消费的上游产物另含内容哈希。随机种子、坐标选择、网格、模型权重、单位约定和会改变算法的线程设置应放在 parameters 或显式输入中；只写在研究者记忆里不会进入复用判断。

软件身份是明确登记的信息。规划器不自动证明声明的环境与真正执行的可执行程序一致；项目执行日志应保存版本输出、环境锁定文件、容器摘要或程序哈希。大型软件升级后，即使命令看起来相同，也应按新环境身份重算受影响任务并做参照测试。

### 变化影响矩阵

| 变化 | 可以保留的部分 | 需要重新计算或审查的部分 |
|---|---|---|
| 新增一批母体化合物 | 输入与方法未变的旧配体准备和独立对接 | 新配体分支、全库汇总、排名、多样性和当前候选选择 |
| 新增受体构象 | 原受体各分支的原始分数 | 新构象下的对应任务及集合聚合与验证 |
| 修改一枚配体的质子化 | 其他状态明确且未改变的模型 | 该状态的对接、参数化、MD、能量和选择结论 |
| 替换力场、水或离子参数 | 原结果作为旧模型版本保留 | 新模型的建系、平衡、生产及相应分析；不要接在旧动力学后续跑 |
| 同一轨迹增加后续时长 | 原始已完成轨迹段 | 新续段及使用完整时间范围的统计和图；独立重复数不增加 |
| 新增一个独立运行 | 旧运行及其固定分析 | 新运行分析、系统级汇总和不确定性 |
| 氢键定义从 3.5 Å 改为 3.0 Å | 物理轨迹与无关观测量 | 氢键计算、占有率、比较和受影响解释 |
| 仅修改图例或配色 | 原始计算、分析表和统计 | 对应图形与报告，保留新绘图版本 |
| 新实验标签或新增供体 | 原始分子计算和已冻结外部测试 | 适用的标签表、训练、统计、排名、图形和结论 |

能否复用必须以真实依赖为准。例如先筛 Top 100 再跑 MD，新增分子可能改变 Top 100；旧 MD 可保留为已有观测，但“该候选来自当前筛选前 100”这个选择理由要重新审查。如果全库按某种数据驱动规则重新标准化或拟合描述符变换，旧分子也可能受影响，不能简单声称只补新增条目。

### 规划器的操作顺序

先复制 incremental/workflow.example.json，填写当前项目内的任务。每个配体、模型或运行使用独立任务，最后再设置汇总任务。每个输出由一个任务负责；任务间不能共享可变输出目录中的同一文件。指定的项目根目录必须已经存在，数据路径位于其内。

```bash
python3 incremental/plan_incremental.py plan project/workflow.json \
  --root project --output project/plan_r01.json
```

计划只读取文件并写报告，不运行引擎，也不提交任务。reuse 表示指纹、输出和审查证据均匹配；run 表示前置可用而当前任务无可复用结果；waiting 表示需先完成或重新验收上游；blocked 表示缺少文件、存在待填信息或上游受阻。存在 blocked 时返回退出码 2；run 和 waiting 本身不是程序错误。

依当前计划在已验证的实际执行器中完成任务，先填写 review_draft.json 的实际 run_id、退出码、日志、执行时间和证据路径，再用 bind-review 生成绑定输出与证据字节的待审快照。研究者审查该快照后，填写审查人、带时区的审查时间、通过检查和 accepted 状态，随后才可 record。输出文件必须非空；零命中等情况写明确的空结果记录和计数，不能用零字节文件表示成功。

```bash
python3 incremental/plan_incremental.py bind-review project/workflow.json \
  --root project --task prepare_L001 \
  --review reviews/prepare_L001_draft.json \
  --output project/reviews/prepare_L001.json
```

bind-review 只绑定当前文件的 path、sha256 和 bytes，并把审查状态重置为 pending。它不执行科学验收。record 会同时核对输入指纹、全部输出快照、日志和证据快照；任一被审查文件改变后，旧审查不能再次为它背书。输入指纹只能定义打算执行什么，不能代替对实际输出的审查。

```bash
python3 incremental/plan_incremental.py record project/workflow.json \
  --root project --task prepare_L001 --review reviews/prepare_L001.json \
  --output project/state_r01.json

python3 incremental/plan_incremental.py plan project/workflow.json \
  --root project --state project/state_r01.json \
  --targets dock_L001 --output project/plan_r02.json
```

后续 record 调用传入最近 state，并将新状态写到新文件。状态更新应由一个协调进程串行完成，不能让多个 worker 各自写出并覆盖“最新状态”。本包脚本不提供分布式锁或多用户数据库；大型项目应交由已验证的工作流系统或事务数据库管理。每次输出使用新版本名，脚本拒绝覆盖已有文件。

### 验收与边界

先用一个小项目证明四件事：修改 A 分支输入只使 A 及相关汇总失效；B 分支可继续复用；输出被修改或证据丢失时不能复用；依赖环和两个任务写同一输出被拒绝。将新增任务、状态变化、指纹组成变化和排除原因归档。只有配置里声明的依赖才可被检查，漏报的数据库更新或外部模型变化不会被脚本自动发现。

本工具验证审查记录是否存在且一致，不独立验证审查意见是否科学正确。accepted 记录必须由负责该分析的人根据真实日志和科学检查填写。指纹变化说明要重新评估可复用性，不能据此判断科学结论变化的大小。
