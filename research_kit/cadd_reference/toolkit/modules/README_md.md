# 动力学增量模块的可填写契约

本目录的 I09 至 I15 文件将手册中的科研问题、输入身份、参数决策、结果字段和复用条件整理成可填写的 JSON。它们用于项目登记、审查和工具间交接，**不是 Amber mdin、GROMACS mdp、PLUMED 输入，也不是已经验证的 OpenFE 或 QM/MM 配置**。当前未替任何具体体系完成建系、参数化、采样或分析。

## 文件与使用顺序

| 文件 | 用途 | 先完成的审查 |
|---|---|---|
| `I09_state_water.example.json` | 化学状态、参数敏感性、恒定 pH 可行性和水网络 | 状态、原子映射、参数及含水轨迹是否可用 |
| `I10_pocket_panel.example.json` | 受体集合、动态口袋与隐蔽位点 | 结构质量、残基映射、轨迹权重来源和对照 |
| `I11_membrane_glycan.example.json` | 膜、脂质、糖型及跨引擎转换 | 生物环境证据、力场组合、连接及特殊相互作用 |
| `I12_special_chemistry.example.json` | 金属、辅因子、共价和 QM/MM 分支 | 氧化态、电荷、自旋、连接和问题是否涉及化学变化 |
| `I13_free_energy_network.example.json` | RBFE 网络和 ABFE 项目 | 端点状态、结合模式、原子映射、两腿和协议 |
| `I14_sampling_protocol.example.json` | 增强采样、重加权与动力学 | 具体采样瓶颈、CV、目标状态及偏置方法 |
| `I15_dynamic_network.example.json` | 动态网络、变构和界面分析 | 可比轨迹、残基映射、源目标区域和构图规则 |

复制所需模板为项目文件，保留原模板不变。先填写研究问题和输入，再填写方法与验收依据；只有真实输出存在后才登记结果。各模块可以独立启用，前提是其输入和前置科学审查已满足。不需要为了启用 I13 而机械完成所有其他模块。

## 通用字段的填写规则

`schema_version` 是这组契约的格式版本，不是模拟软件版本；`module_id` 标识模块；`status` 初始为 `draft`。`contract_id` 与 `project_id` 由项目分配，不用一个名字同时代替母体、化学状态、物理模型和重复。`research_question` 应写成具体待比较问题，`decision_to_support` 说明结果将支持什么资源或研究决策。

`null` 表示未知或尚未填写，`__FILL__` 是明确占位符，`rows: []` 表示尚未导入记录。**空结果不等于零结果，空清单也不等于已证明该组分不存在。** 对不适用的字段可保留空值，但应在相应理由字段或 `qc.unresolved_issues` 中说明“不适用”的依据。

每个表提供 `row_template` 和 `rows`。`row_template` 说明一条记录有哪些字段，不是一条真实观测。使用时复制其结构到 `rows`，填写真实值，可重复增加多行。不要把模板行计入候选数、样本数或重复数。结果表按观测层次保留 `system_id`、`model_variant_id`、`replicate_id` 及时间信息。

文件记录中的 `path` 应指向项目中真实存在的文件，`sha256` 填写其实际校验值；复制、重命名或修改输入后要核对身份。原始输入、处理后结构、拓扑、轨迹及分析结果分别登记，不能用同一个校验值代替整套体系。`source_records` 与 `reference_keys` 记录结构、实验及方法依据。

`execution.enabled` 初始为 `false`，表示未启用执行声明；即使用户将它改成 `true`，本契约也不会执行计算。运行仍需要另行生成经审查的引擎配置、使用实际软件进行预处理，并检查输出。`engine_version`、`protocol_version`、`environment_manifest` 需对应真实运行环境。OpenFE 所采用的具体协议和运行引擎须单独确认，不能因已有 Amber/GROMACS 就推定它可直接运行。

`qc.status` 初始为 `pending`。记录每个检查的对象、判据、证据文件和结论；程序能解析 JSON 或检查字段存在，只能说明格式层面通过，不能自动给出化学、采样或科学解释合格。`output_artifacts` 与 `plots` 中的 `not_generated` 应在真实文件产生并核验后更新，不能先改成完成再补文件。

## 各模块必需字段与参数含义

### I09 化学状态与水网络

至少填写化学状态行、原子映射、参数来源和轨迹记录。`population_estimate` 只填写有来源的状态占比，未知保持空值；不同状态不是独立随机重复。`fixed_state_comparison.factor_definitions` 应说明每次改变的是化学态、电荷方案还是其他物理模型因素。

水分析必须明确 `contains_water`，并保留匹配拓扑。`water_site_definition` 以空间位置定义位点，`water_molecule_identity_mapping` 跟踪分子身份，不能混用。水寿命需填写进入、退出、短暂间断容忍和删失规则；`saved_interval` 是原始输出频率，分析不能恢复它未保存的事件。

GIST 的网格中心和间距用 Å，`grid_dimensions_voxels` 是体素个数，不是物理长度；体相数密度字段的单位是 Å⁻³。明确密度量与每水分子归一化量、低占有掩膜以及离子/共溶质的处理。恒定 pH 分支只有在实现、支持组分和标定依据明确后启用。

### I10 受体集合与口袋

至少填写结构或轨迹来源、残基映射、局部特征、聚类及口袋检测定义。每个代表构象都应能追溯到真实结构或轨迹帧。`statistical_weight` 必须与 `weight_source` 配套；有偏或自适应样本不能直接按帧数赋平衡权重。

`detector_pocket_label` 是单次软件输出编号，`pocket_id` 是项目中跨构象匹配的身份。填写未识别、缺失、遮挡和关闭的编码方法，不能全部填零。受体集合选定后，用独立或按预设划分的已知对照检查其新增信息。

### I11 膜与糖链

至少填写蛋白构建体、膜方向、上下膜叶组成及其证据、糖型/连接、完整力场组合。未知膜组成或糖型采用简化模型时，必须填写 `simplification_rationale`，并保留模型分支身份。

压力或张力集合、膜法向、压缩率及电位定义须来自具体协议。`area_method` 明确是否考虑蛋白占据面积、混合脂质和曲率。糖链的连接和环构型必须与残基命名相符。跨引擎转换须审查 1–4 缩放和特殊相互作用；固定坐标能量比较需记录可比项与约束条件。

### I12 特殊化学体系

至少填写化学态证据、配位/共价连接和所选路线。`selected_route` 应说明采用成键金属模型、经验证的非键模型、QM/MM，或相应组合的理由，不能仅写软件名。

氧化态、总电荷与相关自旋信息必须先确定再生成参数。涉及 QM/MM 时，QM 区、边界、电子结构方法和环境表示共同构成模型；空缺不能用引擎默认值代替审查。共价加合物需保留反应前后原子对应，端点能量切分应重新检查。`independent_validation_target` 应区别于用于拟合的目标。

### I13 自由能网络

RBFE 至少需要明确的两个端点、映射、复合物腿和溶剂腿、方向与原始自由能数据。模板固定说明 ΔΔG(A→B) = ΔGbind(B) − ΔGbind(A)；正值代表 B 的结合较不利。分析输出若采用不同约定，必须显式转换并记录，不能只改列名。

λ 状态数与采样时长均留空，应按具体边和诊断结果确定。`raw_energy_output_definition` 说明实际保存的是导数、相邻态能量还是完整跨状态能量；估计器需与输入匹配。统计误差、独立重复差异和模型局限分别记录。

带电变化须在计算前填写两条腿一致的处理方案；加中和离子不等于完成全部有限尺寸审查。ABFE 另需填写约束势能、锚点、添加/释放、标准态、对称性及多位姿处理。没有对应数据时不得填写预测亲和力。旧边复用后，新增网络仍需重新汇总、拟合和传播误差。

### I14 增强采样与动力学

首先填写 `primary_goal`，区分构象探索、平衡分布/自由能和速率/停留时间。CV 应包括公式、原子、单位、周期性、PBC 和对齐处理；同名距离或角度并不自动表示相同变量。

Umbrella 和 metadynamics 的参数不提供万能默认值。重启时偏置历史与引擎 checkpoint 要保持一致。重加权方法须匹配偏置类型，权重集中程度和时间相关性分别检查。动力学分支需记录独立事件、初始分布、删失和实际时间重建方法；普通有偏轨迹时间不能直接当真实时间。

MSM 需保留每条连续轨迹的边界、转移计数与滞后时间单位。缺失区间、不同重复或不同条件之间不创造首尾跳转。对统计稀疏的转移，应保留不确定性及限制，而不是仅交付一个首达时间。

### I15 动态网络与界面

至少填写残基映射、源目标区域的独立依据、对齐、节点定义、接触规则、相关度和边权转换。`nodes` 中的矩阵/图编号与生物学残基位置分开登记，避免因链或 isoform 改变而错配。

零相关、缺失数据和不接触不是同一种状态，应分别处理。社区编号在不同运行之间需要映射。PRS 模板明确“行是扰动源，列是响应目标”；实际工具定义若不同，需先核对后转换。网络路径与中心性用于提出机制假设，不自动说明因果方向。

## 结果和增量更新

每次更新填写 `parent_contract_id` 和 `changed_fields`，并在 `decision_reason` 说明为什么复用或使结果失效。将复用和失效的真实 artifact ID 分别列入相应清单。只改配色通常仅更新图形；改分析定义通常从原始数据重分析；改化学态、参数、连接或物理环境通常需要新的模型与采样。具体判断应使用对应模块正文中的适用范围，不能只依据文件名是否改变。

模板中的 `sop_recompute_rules` 用于提醒审查，不是自动依赖判定器。对新增轨迹或新网络边，旧输入可能仍有效，但汇总统计、排名和报告会受影响。不得因为单个新文件通过格式检查就跳过所有下游更新。
