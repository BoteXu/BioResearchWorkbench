# I23 模块接口与数据身份契约

版本 3.0.0

### 触发条件与身份层级

当同一项目包含多批候选、多种化学状态、多套受体、多条轨迹或多个生物数据批次时，先建立本模块。它的目的在于保证每个分数、每张图、每条结论都能回到准确的研究对象。输入为项目问题、既有文件清单、拟增加的数据与已有编号；输出为实体登记表、任务清单、路径表和字段字典。

化学实体至少区分 source_record_id、parent_id、stereoisomer_id、state_id、conformer_id。受体至少区分 target_id、species、isoform_id、construct_id、receptor_model_id。计算至少区分 method_version、task_id、run_id、replicate_id、segment_id 和 analysis_version。来源记录合并到同一母体时保存交叉表；同一母体的状态或构象被排除时，母体本身不应从数据库无记录消失。

同一条记录可以具有多层身份。例如 L001 是母体，L001_S02 是特定化学状态，L001_S02_C03 是构象；与 R002 对接得到的 pose_id 经参数化形成 system_model_id，随后 rep03 的 seg004 是该运行的续段。这个层级不能压成一个笼统的“ligand_name”。文件名只是定位辅助，身份字段才负责连接数据。

### 必需字段与关系检查

| 记录类型 | 至少需要的字段 | 验收规则 |
|---|---|---|
| 化学输入 | parent_id、state_id、规范化分子图、净电荷、立体信息、来源版本 | 图和状态可回溯；ID 无冲突 |
| 受体模型 | 序列与编号映射、结构来源、构建体、修复与化学状态版本 | 目标序列和结构对应明确 |
| 计算任务 | task_id、输入引用、参数、程序版本、代码、种子、输出路径 | 无依赖环；无两个任务写同一输出 |
| 轨迹段 | system_model_id、replicate_id、segment_id、时间范围、拓扑和重启来源 | 时间连续性及原子顺序核对通过 |
| 观测数据 | entity_id、observable_id、value、unit、statistical_unit、analysis_version | 数值单位与统计对象明确 |
| 实验或组学 | sample_id、donor_id 或独立实验单位、批次、条件、终点、缺失原因 | 计数、配对与生物重复可重建 |

先检查主键唯一性，再检查外键存在性，最后检查关系是否符合物理含义。一个 parent_id 可以对应多个 state_id，但一次固定电荷 MD 的 system_model_id 不能在不换模型记录的情况下切换配体化学状态。一个 donor_id 可以包含多种细胞状态，不应把细胞 ID 直接当作供体级独立样本。

原始文件保持只读。规范化结果写到新路径，保留原始字节的 SHA256。输入文件路径、显示名称、文件大小与内容哈希分别保存；同内容改名和同名改内容是不同事件。对大轨迹校验需安排 I/O 时间，不能因哈希耗时而把“文件存在”视为等价验证。

### 数据导出与接口

分子图和三维坐标优先按下游工具支持的格式保存，并伴随身份表；PDBQT 不能成为配体键级和化学身份的唯一来源。矩阵和长表保存字段类型、缺失值编码、单位、索引定义和排序。图形程序读取已经定义好的观测数据，避免在同一绘图脚本里悄悄重定义氢键、计算能量、筛选时间区间和添加显著性。

包内 workflow.example.json 采用显式输入引用：外部文件用 path，上游产物用 task 和 output。依赖关系由这些引用与 depends_on 共同构成；生产文件不能再伪装成独立原始输入。模块登记 modules/module_registry.json 描述研究模块的接口，增量脚本中的 workflow.json 描述具体项目任务，两者层级不同。

### 验收与失败回退

通过条件是身份唯一、关系一致、单位完整、路径可解析、输出不冲突、未完成项明确可见。发现同名异物、化学状态不明、原子映射丢失或样本来源不明时，暂停受影响分支，从原始输入重建映射。不要用排序行号替代缺失的稳定 ID。
