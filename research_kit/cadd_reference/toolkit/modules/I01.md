# I01 多参考药效团与形状查询的增量验证

版本 3.0.0

### 启用条件与最少输入

当首轮筛选几乎只返回参考配体的近邻，新增了另一种结合构象，或需要判断某个药效团特征是否过度限制库覆盖时，启用本模块。本组 I01 至 I08 是研究操作规范与数据接口；Pharmit、RDKit、mmpdb、OpenFE、BoTorch 等具体计算仍需准备相应环境、项目输入及审核。配套增量规划和排名比较脚本不等于这些科研模块已经自动执行。

Pharmit 支持药效团和形状查询；同时输入受体与配体时，两者需要已经处于正确的相对坐标关系，上传任意朝向的两份结构不会自动完成对接。[IS01] 输入至少包括 reference_complex.pdb、reference_ligands.sdf、reference_registry.json、query_features.json 和 independent_controls.json。

reference_registry 每条记录 reference_id、parent_id、state_id、receptor_state_id、结构来源、坐标哈希、原子映射、实验终点和开发或评价角色。预测模型保留 model 类型。每个特征记录 feature_id、类型、中心坐标及单位、半径、方向规则、必需或可选、来源原子与残基，以及哪些参考支持它。排斥体积也需要来源和版本。query_id 绑定全部设置，截图不能代替输入文件。

### 执行顺序与参数依据

1. 按共同口袋对齐参考，保存变换矩阵与拟合残基；核对结构域、缺失环、化学状态与配体空间关系。说明使用局部或全局拟合的原因。
2. 分别生成每个参考的查询，再构建共同特征查询。共同接触是候选锚点，是否设为必需仍取决于证据；保留可能代表另一结合模式的独有特征。
3. 冻结组合逻辑。并集允许多种模式，交集要求满足全部条件；互斥受体状态的查询不宜无解释地取交集。每条命中保存 query_id 和 matched_feature_ids。
4. 对必需特征做删除或适度放宽的消融检查，使用同一开发集合记录母体召回、骨架覆盖、通过率和冲突。改变规则的理由先于结果写下。
5. 冻结正式查询，在未参与选特征或调容差的评价集合运行。小样本显示逐个对照；没有独立评价时标为探索性。
6. 以保留分子图和原子映射的 SDF 交付对齐候选，再进行实际对接和受体冲突审查。查询对齐、对接搜索和位姿复评分别登记。

形状比较前完成所声明的对齐。RDKit ShapeTanimotoDist 对预先对齐的分子返回形状距离；若展示相似度，应明确转换为 1−distance。[IS02] 对齐方法、构象 ID、氢处理和网格设置均进入协议。特征半径和可选数量用独立对照及合理敏感性检查选择，不通过不断扩大容差来制造漂亮召回率。

### 验收 失败回退与计算投入

最低检查为自匹配通过、供受体身份正确、坐标单位一致、开发与评价无交叉、母体去重以及查询能从文件重建。一个分子的多个构象不能当多个成功命中。若结果异常，依次查对齐、特征化学含义、排斥体积、参考模式相容性及构象覆盖；验证仍不成立时，不用该查询硬过滤全库。先用对照和小批库判断增益，再扩大三维检索；多个冗余查询增加任务数，不自动增加信息。

### 输出 可视化与失效条件

输出 query_registry、query_hit_table、aligned_hits.sdf、ablation_report 和 query_validation。I01-P1 为同一相机下的多参考与特征叠合；I01-P2 为特征消融后召回与通过率；I01-P3 为按独立母体计数的查询 UpSet 图；I01-P4 为共同评价集的新旧查询对照。三维图标明半径、单位与版本。结论限于“符合该结构查询”，不能直接升级为结合、抑制或激动。

仅增加候选且查询、状态和构象政策不变时，只搜新增集合并更新全库汇总。改变查询、对齐基准或参考化学状态后，相关过滤与排名重算；有效且输入不变的原始对接可以保留。新增参考并不自动构成独立验证，来源重叠须在证据表中可见。
