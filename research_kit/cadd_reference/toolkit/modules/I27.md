# I27 排名变动与图形版本发布

版本 3.0.0

### 排名比较的输入契约

本模块在候选库增加、实验反馈、评分模型更新或选择规则改变后使用。输入是两份母体层级的候选快照，而非逐位姿输出。每份快照声明 snapshot_id、comparison_key、score_model、score_name、unit、direction，并逐行列出 parent_id、status 和 value。一个母体只出现一次；状态聚合和受体集合聚合在上游按固定规则完成。

失败和未计算的 value 使用 null，并分别标为 failed 或 not_evaluated。不将失败写成极差分数，不把未测当阴性。选择药效或实验终点比较时，还须确认终点、构建体、条件和删失规则可比；同名字段不是可比性的证据。

### 排名与分数的不同解释

先报告共同已评分母体数量及其对两份库的覆盖率，再比较共同成员的排序。新增一个高分候选会使旧成员的全库名次下降，即使所有旧分数完全不变。因此全库 rank_change 与在共同成员中重新排名后计算的 Spearman 应同时解释，不能只给相关系数。

包内 compare_rankings.py 对共同成员重新计算平均并列秩，再计算相关；少于 3 个共同成员或秩常数时输出不可计算原因。Top N 在边界纳入所有完全相同的并列分数，所以实际数量可能大于 N。Jaccard 使用两组 Top 集合的交并比；它反映成员重叠，不评判哪一版更准确。脚本不输出无依据的显著性 p 值。

不同 score_model 默认拒绝直接比较。确需进行跨评分版本的排名稳定性评估时显式使用 allow-model-change；此时不计算分数差。即使同模型得到分数差，也仅表示该评分定义下的数值变化，不换算成真实亲和力、效力或治疗效果。

```bash
python3 incremental/compare_rankings.py project/ranking_r01.json \
  project/ranking_r02.json --top-n 20 \
  --output project/rank_change_r02.json

python3 visualization/plot_incremental.py rank-change \
  project/rank_change_r02.json --output-prefix project/fig_rank_r02

python3 visualization/plot_incremental.py reuse \
  project/plan_r02.json --output-prefix project/fig_reuse_r02
```

两个出图入口读取已生成报告，分别输出 SVG 和 PNG。需要中文标注时可指定 font-file；颜色、标题、布局改动保留新的绘图版本。图形导出的格式和分辨率写入报告，不以截图替代原始矢量图。[IE09]

### 图形与结论发布清单

每张图保存 figure_id、figure_version、输入表路径与哈希、分析版本、绘图脚本哈希、单位、选择条件、统计单位、误差定义、排除规则和图注。结构图还保存原子选择、视角、对齐、参考结构及颜色图例；轨迹视频保存对应时间范围、帧间隔、播放速度、PBC 和拟合方式。播放速度不等于分子真实动力学速度。

交互浏览与论文输出分别准备。交互视图可以帮助查看单个候选、状态和运行；正式静态图应能在不操作界面的情况下解释主要比较。不要把只在交互悬停中出现的关键单位或样本数量留到静态导出后消失。

图 I27-P1 为共同成员的新旧全库排名散点；图 I27-P2 为 Top 集合成员变化；图 I27-P3 为候选证据变化矩阵。I27-P1 已有基础作图程序，后两图提供数据规范供项目适配；没有数据时保留空模板，不制造演示“命中”作为研究结果。
