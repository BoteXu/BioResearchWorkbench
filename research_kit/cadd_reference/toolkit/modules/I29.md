# 73 I29 tREMD 与 REST2 的协议及交换谱系

最低输入：replica_protocol；state_table；hot_region_atom_mapping；unscaled_reference；engine_capability_receipts。



## 操作与 QC

先决定采样的是温度还是 Hamiltonian。tREMD 使用各状态实际热浴温度；本节多拓扑 REST2 路线的实际热浴维持参考温度，effective temperature 是缩放标签，不能再把全部热浴同时升到该标签温度。记录系综、压力项、约束/自由度、原子顺序及交换实现；不同体系不能仅因原子数相同就交换。[N01、N02]

REST2 区分 hot–hot、hot–cold 与 cold–cold 相互作用。经典缩放记为 λ、√λ 与 1，其中 λ=Tref/Teff；实际工具对哪些项缩放必须逐项核实。PLUMED partial_tempering 的具体实现有力场依赖，不能把理想分区公式当作全部键角、CMAP 或特殊项都已自动正确处理的证明。[N02、N03]

按精确原子映射标记 hot 区，保留共价边界、配体、辅因子、金属和周期排除项的决定。使用展开拓扑；先比较 scale=1 与未缩放参考，再用受控缩放核对预期项及未缩放项。保存分项能量/力与工具版本；发现不支持的项时返回主引擎或专用已验证适配，不删除物理项换取运行成功。

用试跑能量分布、实际交换日志和主要构象观测量调整状态梯度与交换间隔。相邻接受率、端到端往返及 state 驻留共同检查，没有适用所有体系的固定接受率或往返次数。还要核对构象盆地是否真正互通；温度标签往返不能代替构象混合。

分别保留连续 walker 与固定 thermodynamic state 的轨迹/时间轴；交换会改变两种索引的对应关系。目标态统计使用目标热力学态或合法重加权；状态轨迹不能当无偏连续动力学轨迹用于普通速率推断。相互交换的 replicas 不是额外独立重复，独立启动的完整交换批次另记 campaign_id。

每次恢复核对整组检查点、相同交换步/状态指派、每状态拓扑及共同协议版本。单个状态落后或丢失时不能无记录拼接；保留恢复分支。资源按状态数×完整批次数估算，同时记录实际 MPI/GPU 分配和队列回执；本模板只规划，不启动 replica exchange。



## 验收及失败回退

参考缩放和状态映射通过服务器核查，交换与构象混合诊断完整，目标态统计和恢复谱系可追溯；否则 pending 或 restricted，不凭交换率宣布收敛。
